# 노션 견적서 웹 뷰어 (invoice-web) MVP PRD

## 핵심 정보

**목적**: 발행자가 Notion DB에 작성한 견적서를 동기화하여 클라이언트가 웹 링크로 확인하고 PDF로 다운로드할 수 있는 서비스
**사용자**: 프리랜서/1인 사업자(발행자) + 클라이언트(수신자)

---

## 사용자 여정

### 발행자 여정

```
1. 랜딩 페이지 (/)
   ↓ 회원가입/로그인 클릭

2. 회원가입 페이지 or 로그인 페이지
   ↓ 인증 성공 → 자동 리디렉션

3. 견적서 목록 페이지 (/dashboard/invoices)
   ↓ (노션 연동 미완료 시 → 노션 설정 페이지로 자동 이동)
   ↓ (노션 연동 완료 시 → 견적서 목록 표시)

   [미연동 상태] → 노션 설정 페이지 → OAuth 연결 → DB ID 등록 → 견적서 목록 페이지
   [연동 완료 상태] → 견적서 목록 페이지 → 동기화 버튼 클릭 → 목록 갱신

4. 견적서 목록 페이지에서:
   ↓ 견적서 행 클릭 → 견적서 상세 페이지
   ↓ 공유 링크 생성 버튼 클릭 → 공유 토큰 생성 → 링크 복사

5. 견적서 상세 페이지 (/dashboard/invoices/[id])
   ↓ 공유 링크 생성 or 복사 → 클라이언트에게 전달
```

### 클라이언트 여정

```
1. 발행자로부터 공유 링크 수신 (이메일/메신저)
   ↓ 링크 클릭

2. 공개 견적서 뷰어 페이지 (/view/[token])
   ↓ 토큰 유효성 검사

   [유효한 토큰] → 견적서 내용 표시 → PDF 다운로드 버튼
   [만료/무효 토큰] → 에러 페이지 표시

3. PDF 다운로드 버튼 클릭 → PDF 생성 → 다운로드 완료
```

## 기능 명세

### 1. MVP 핵심 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F001** | 노션 OAuth 연결 | 노션 계정 OAuth 인증으로 액세스 토큰 발급 및 저장 | 노션 DB 접근의 전제 조건 | 노션 설정 페이지 |
| **F002** | 노션 DB ID 등록 | 연동할 노션 데이터베이스 ID 입력 및 저장 | 동기화 대상 DB 지정 필수 | 노션 설정 페이지 |
| **F003** | 견적서 동기화 | 노션 DB 페이지를 읽어(`client.databases.query()`) Supabase에 Invoice 레코드 전체 덮어쓰기(upsert, `notion_page_id` 기준) | 핵심 데이터 수집 | 견적서 목록 페이지 |
| **F004** | 견적서 목록 조회 | 동기화된 견적서를 상태/날짜 기준으로 표 형태로 표시 | 발행자의 핵심 작업 공간 | 견적서 목록 페이지 |
| **F005** | 견적서 상세 조회 | 단일 견적서의 전체 데이터(항목, 금액, 메모) 표시 | 공유 전 내용 확인 필수 | 견적서 상세 페이지 |
| **F006** | 공유 링크 생성 | 견적서에 고유 shareToken을 생성하여 공개 URL 발급 | 클라이언트 전달의 핵심 수단 | 견적서 목록 페이지, 견적서 상세 페이지 |
| **F007** | 공개 견적서 뷰어 | 인증 없이 shareToken으로 견적서 내용을 웹에서 열람 | 클라이언트의 유일한 접근 경로 | 공개 뷰어 페이지 |
| **F008** | PDF 다운로드 | 뷰어 페이지에서 @react-pdf/renderer로 PDF 파일 생성 및 다운로드 | 클라이언트의 핵심 니즈(보관/서명용) | 공개 뷰어 페이지 |

### 2. MVP 필수 지원 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F010** | 기본 인증 | 이메일/비밀번호 회원가입, 로그인, 로그아웃 (Supabase Auth) | 발행자 데이터 격리 및 보호 | 로그인 페이지, 회원가입 페이지 |
| **F011** | 노션 연동 상태 확인 | 현재 OAuth 연결 상태 및 등록된 DB ID 표시 | 발행자가 연동 상태를 파악해야 동기화 가능 | 노션 설정 페이지 |

### 3. MVP 이후 기능 (제외)

- 견적서 상태 수동 변경 (accepted/rejected 직접 조작)
- 이메일 발송 기능 (링크 복사로 대체)
- 클라이언트 수락/거절 응답 기능
- 견적서 직접 편집 (노션에서 수정 후 재동기화로 대체)
- 알림 시스템 (이메일/푸시)
- 팀 계정/멤버 관리
- 견적서 템플릿 기능
- shareToken 만료/갱신 기능 (MVP에서는 만료 없음, 이후 유효기간 옵션 추가 예정)

## Notion DB 컬럼 구조

노션 데이터베이스에 아래 프로퍼티를 생성해야 동기화가 정상 작동합니다.

> **발행자 정보 처리**: 발행자 이름·연락처는 Notion DB 컬럼이 아닌 Supabase `profiles` 테이블에서 관리합니다. 공개 뷰어 페이지에서 `user_id`로 JOIN 조회합니다.

| 프로퍼티명 | 노션 타입 | 필수 여부 | 설명 |
|-----------|-----------|---------|------|
| `Name` | Title | 필수 | 견적서 제목 (노션 기본 타이틀 컬럼) |
| `Client Name` | Rich Text | 필수 | 클라이언트 이름 |
| `Client Email` | Email | 선택 | 클라이언트 이메일 |
| `Issued At` | Date | 필수 | 발행일 |
| `Due Date` | Date | 선택 | 견적 유효기한 |
| `Status` | Select | 필수 | `draft` / `sent` / `accepted` / `rejected` |
| `Total Amount` | Number | 필수 | 합계 금액 (원) |
| `Tax Included` | Checkbox | 선택 | 세금 포함 여부 |
| `Note` | Rich Text | 선택 | 메모 및 특이사항 |
| `Items` | Rich Text | 필수 | JSON 문자열로 견적 항목 배열 저장 (`[{"name":"...","quantity":1,"unitPrice":100000,"subtotal":100000}]`) |

> **Items 컬럼 설명**: 노션의 Relation/Rollup은 복잡도가 높아 MVP에서는 Rich Text에 JSON 문자열로 저장. 동기화 시 `JSON.parse`로 파싱하여 `InvoiceItem[]`으로 변환.

### 주요 Request/Response 구조

```ts
// POST /api/invoices/sync
// Request: body 없음 (user_id는 Supabase 세션에서 자동 추출)
// Response (성공)
{ success: true, data: { synced: number, created: number, updated: number } }
// Response (실패 — 노션 미연동)
{ success: false, data: null, message: "노션 연동이 필요합니다." }
// Response (실패 — 노션 토큰 만료)
{ success: false, data: null, message: "노션 연동이 만료되었습니다. 재연동이 필요합니다." }

// POST /api/invoices/[id]/share
// Request: body 없음
// Response (성공)
{ success: true, data: { shareToken: string, shareUrl: string } }
// Response (실패 — 이미 존재)
{ success: true, data: { shareToken: string, shareUrl: string } } // 기존 토큰 그대로 반환

// GET /api/view/[token]
// Response (성공)
{ success: true, data: { invoice: Invoice, issuer: { name: string, contact: string } } }
// Response (실패)
{ success: false, data: null, message: "유효하지 않은 링크입니다." }
```

## 에러 처리 정책

| 에러 상황 | 발생 지점 | 처리 방법 |
|----------|----------|---------|
| Notion OAuth 토큰 만료/무효 (401) | F003 동기화 | `notion_integrations` 상태를 `error`로 변경 + 사용자에게 재연동 안내 토스트 + 설정 페이지 이동 버튼 표시 |
| 잘못된 DB ID (ObjectNotFound) | F002 저장, F003 동기화 | "데이터베이스를 찾을 수 없습니다. DB ID를 확인해주세요." 에러 메시지 표시 |
| Notion API Rate Limit (429) | F003 동기화 | SDK 내장 자동 재시도(최대 2회) 후 실패 시 "잠시 후 다시 시도해주세요." 안내 |
| Items JSON 파싱 실패 | F003 동기화 | 해당 페이지는 `items: []`로 저장 후 계속 진행, 오류 건수 응답에 포함 (`errors` 배열) |
| DB 스키마 불일치 (컬럼 없음) | F003 동기화 | 누락 필드는 기본값 처리(null/빈값), 치명적 오류는 `errors` 배열에 포함 |
| 무효/존재하지 않는 shareToken | `/view/[token]` | "유효하지 않은 링크입니다." 에러 페이지 표시 |
| 동기화 중 로딩 상태 | F003 UI | 동기화 버튼 비활성화 + `LoadingSpinner` 표시 → 완료 시 성공/실패 Sonner 토스트 |

## 화면별 User Flow 요약

### Flow 1: 최초 설정 (발행자 신규 가입)

```
랜딩 페이지
  → 회원가입 버튼 클릭
  → 회원가입 페이지 (이메일 + 비밀번호 입력)
  → 가입 성공 → 자동 로그인
  → 견적서 목록 페이지 (노션 미연동 안내 배너 표시)
  → "노션 연결하기" 클릭
  → 노션 설정 페이지
  → "노션으로 연결" 버튼 클릭 → 노션 OAuth 팝업/리디렉션
  → OAuth 승인 → 콜백 처리 → 액세스 토큰 저장
  → 노션 DB ID 입력 폼 표시 → DB ID 입력 → 저장
  → 견적서 목록 페이지로 이동
```

### Flow 2: 견적서 동기화 및 공유 링크 생성 (발행자 반복 사용)

```
견적서 목록 페이지
  → "노션 동기화" 버튼 클릭
  → POST /api/invoices/sync 호출
  → 노션 DB 페이지 목록 읽기 → Supabase upsert
  → 목록 갱신 (TanStack Query invalidate)
  → 특정 견적서 행에서 "공유 링크 생성" 클릭
  → POST /api/invoices/[id]/share 호출 → shareToken 생성
  → 링크 복사 버튼 활성화 → 클립보드 복사
```

### Flow 3: 클라이언트 견적서 열람 및 PDF 다운로드

```
공유 링크 수신 (/view/[token])
  → 공개 뷰어 페이지 진입
  → GET /api/view/[token] 호출
  → 유효한 토큰: 견적서 내용 렌더링
  → "PDF 다운로드" 버튼 클릭
  → @react-pdf/renderer로 PDF Document 생성
  → 브라우저 다운로드 트리거
  → 다운로드 완료
```
